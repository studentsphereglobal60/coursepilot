7 Beginner SQL Projects to Practise Database Skills

The fastest way to make SQL feel useful is to ask questions of data. These seven projects take you from simple filtering to joins, summaries and data-quality checks. You can build them with a local database or a browser-based SQL practice tool—no paid software is required for the learning exercises.

Before you start
  • Know the basics of SELECT, WHERE and ORDER BY. If you are completely new, try the free interactive SQLBolt lessons first.
  • Use fictional, public or properly licensed sample data. Never upload private customer, student, employer or financial records to a public playground or portfolio.
  • Examples below use conventional SQL syntax. Date functions and a few details can vary between SQLite, PostgreSQL, MySQL and SQL Server, so check the documentation for the database you choose.

1. Personal library database

Scenario: A small community library wants to keep track of books and which members have borrowed them. Create two tables: books (book_id, title, author, category, published_year) and loans (loan_id, book_id, member_name, loan_date, return_date).

Try these questions: Which books were published after 2015? Which books are currently on loan? How many books are there in each category?

SELECT title, author
FROM books
WHERE published_year > 2015
ORDER BY title;

SELECT category, COUNT(*) AS book_count
FROM books
GROUP BY category
ORDER BY book_count DESC;

Skills: selecting columns, filtering rows, sorting and basic aggregation. Extension: join books to loans to show each borrowed title and its return status.

2. Student results summary

Scenario: Use synthetic student and assessment tables. The students table contains student_id and student_name; the assessments table contains assessment_id, student_id, subject and score.

Try these questions: What is the average score in each subject? How many assessment records are below 50? Which students have more than one assessment?

SELECT subject,
       ROUND(AVG(score), 1) AS average_score,
       COUNT(*) AS assessment_count
FROM assessments
GROUP BY subject
ORDER BY average_score DESC;

SELECT student_id, COUNT(*) AS attempts
FROM assessments
GROUP BY student_id
HAVING COUNT(*) > 1;

Skills: AVG, COUNT, GROUP BY and HAVING. Extension: join the two tables to display student names. Keep the data fictional; real student records are sensitive.

3. Shop inventory tracker

Scenario: A small shop has a products table with product_id, product_name, category, unit_price and stock_quantity.

Try these questions: Which products have fewer than 10 units left? What is the estimated value of stock in each category? Which products need reordering?

SELECT product_name, stock_quantity
FROM products
WHERE stock_quantity < 10
ORDER BY stock_quantity ASC;

SELECT category,
       SUM(unit_price * stock_quantity) AS stock_value
FROM products
GROUP BY category
ORDER BY stock_value DESC;

Skills: numeric expressions, filtering and grouped totals. Extension: use a CASE expression to label stock as “Reorder” or “In stock”.

4. Online store order analysis

Scenario: Create three related tables: customers (customer_id, customer_name), orders (order_id, customer_id, order_date, status) and order_items (order_item_id, order_id, product_name, quantity, unit_price).

Try these questions: What is the total value of each order? Which products generated the highest sales value? How many orders were placed by each customer?

SELECT o.order_id,
       SUM(oi.quantity * oi.unit_price) AS order_total
FROM orders AS o
JOIN order_items AS oi ON oi.order_id = o.order_id
GROUP BY o.order_id
ORDER BY order_total DESC;

SELECT oi.product_name,
       SUM(oi.quantity * oi.unit_price) AS sales_value
FROM order_items AS oi
JOIN orders AS o ON o.order_id = oi.order_id
WHERE o.status = 'completed'
GROUP BY oi.product_name
ORDER BY sales_value DESC;

Skills: joining related tables, table aliases and aggregate calculations. Extension: include customer names and compare completed with cancelled orders. Decide clearly whether cancelled or refunded orders should count in your analysis.

5. Customer support ticket report

Scenario: A support team stores tickets in a tickets table: ticket_id, category, priority, status, created_at and resolved_at.

Try these questions: How many tickets are open? Which categories receive the most tickets? Which high-priority tickets are still unresolved?

SELECT category, COUNT(*) AS ticket_count
FROM tickets
GROUP BY category
ORDER BY ticket_count DESC;

SELECT ticket_id, category, priority, created_at
FROM tickets
WHERE priority = 'high'
  AND status <> 'resolved'
ORDER BY created_at;

Skills: multiple conditions, date columns and grouped reporting. Extension: calculate resolution time after checking the date-difference function supported by your database. Be explicit about time zones and tickets that have not yet been resolved.

6. Website activity overview

Scenario: Use a synthetic page_events table with event_id, visitor_id, page_path, event_type and event_time. This is practice data—not a way to access another site's analytics.

Try these questions: Which pages received the most page-view events? How many distinct visitors generated events? Which event types were recorded?

SELECT page_path, COUNT(*) AS page_views
FROM page_events
WHERE event_type = 'page_view'
GROUP BY page_path
ORDER BY page_views DESC;

SELECT event_type, COUNT(DISTINCT visitor_id) AS visitors
FROM page_events
GROUP BY event_type
ORDER BY visitors DESC;

Skills: filtering event records, grouping and distinct counts. Extension: compare daily activity using the date-extraction syntax for your database, and explain why an event count is not necessarily the same as a unique-user count.

7. Data quality audit

Scenario: A dataset has missing product names, repeated IDs, negative quantities or inconsistent category labels. Before analysis, write queries that identify records needing review.

Try these questions: Which rows have missing required values? Are any IDs repeated? Are there quantities that should be checked?

SELECT *
FROM products
WHERE product_name IS NULL
   OR product_name = '';

SELECT product_id, COUNT(*) AS occurrences
FROM products
GROUP BY product_id
HAVING COUNT(*) > 1;

SELECT *
FROM order_items
WHERE quantity <= 0;

Skills: IS NULL, grouping, duplicate detection and validation rules. Extension: write a short report that distinguishes confirmed errors from records that merely need human review. Do not delete or overwrite records until you understand the cause.

How to turn a SQL project into a portfolio example

  1. State the question. Explain the real-world problem your project is meant to answer.
  2. Describe the data. List the tables, important columns, source and licence. If you created fictional data, say so.
  3. Show the queries. Include readable SQL, comments and a few representative results. Do not publish personal or confidential information.
  4. Explain the finding. Describe what the query shows and any limits in the data. Avoid claiming that a small sample proves a general trend.
  5. Make it reproducible. Include setup instructions, the database engine/version, schema and steps to run the queries.

Where can you practise SQL for free?

  • SQLBolt — short interactive lessons and exercises for SELECT, filtering, joins and aggregates.
  • PostgreSQL official tutorial — a hands-on introduction to relational database concepts, creating tables, querying, joins and aggregate functions.
  • SQLite documentation — documentation for a lightweight database engine that can be useful for local practice.

The tools above are independent resources. Check their current terms, features and database compatibility before using them. SQL dialects differ; a query that works in one engine may need small changes in another.

Common questions

Do I need to know programming before starting SQL?

No. You can begin with tables, columns and basic queries without knowing a general-purpose programming language. Understanding spreadsheets can help you picture rows and columns.

How many projects should a beginner complete?

Start with two or three projects you can explain clearly. A small project with sensible questions, readable queries and documented limitations is more useful than a long list of unfinished exercises.

Which SQL database should I use?

Choose one beginner-friendly environment and stay with it while learning the fundamentals. SQLite is lightweight; PostgreSQL is a widely used relational database with detailed official learning material. Follow the requirements of your course or target role if they specify a particular database.

Can these projects help me get a data analyst job?

They can help you practise and demonstrate SQL, but projects alone do not guarantee employment. Employers may also expect spreadsheet skills, data visualisation, communication, domain knowledge and experience with larger or messier datasets.

Should I put every query on GitHub?

You can publish a clean, well-documented project if the data licence permits it and the repository contains no secrets or personal information. Include setup instructions so another person can reproduce your work.

Your next step

Pick one project, write three questions you want the data to answer, and solve them with SQL. Then add one extension only after the basic queries work.
