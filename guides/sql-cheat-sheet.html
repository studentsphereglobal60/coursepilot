SQL Cheat Sheet for Beginners

Keep the SQL commands you use most in one place. This beginner-friendly reference covers reading data, filtering, sorting, grouping, joining tables and changing records—with short examples you can adapt to your own practice database.

Before using these examples
  • Examples use broadly familiar SQL syntax. Small differences exist across SQLite, PostgreSQL, MySQL and SQL Server.
  • Run queries on a practice database first. Back up important data before changing records.
  • Use fictional or properly licensed sample data. Never publish private customer, student or employer records.

1. Basic SELECT queries

-- Select every column
SELECT * FROM customers;

-- Select only the columns you need
SELECT first_name, country
FROM customers;

-- Return unique values
SELECT DISTINCT country
FROM customers;

-- Return a limited number of rows
SELECT * FROM products
LIMIT 10;

SELECT chooses columns; FROM names the table. DISTINCT removes duplicate result rows. LIMIT is common in SQLite, PostgreSQL and MySQL; SQL Server uses different syntax.

2. Filter rows with WHERE

-- Exact match
SELECT * FROM customers
WHERE country = 'Canada';

-- Numeric comparison
SELECT * FROM products
WHERE price >= 25;

-- Multiple conditions
SELECT * FROM orders
WHERE status = 'completed'
  AND total_amount > 100;

-- Match a range or a pattern
SELECT * FROM orders
WHERE order_date BETWEEN '2026-01-01' AND '2026-12-31';

SELECT * FROM customers
WHERE email LIKE '%@example.com';

-- Check missing values
SELECT * FROM customers
WHERE phone IS NULL;

Common operators include =, <>, >, >=, AND, OR, IN, BETWEEN and LIKE. Use IS NULL, not = NULL, to test for missing values.

3. Sort and rename result columns

SELECT product_name,
       price AS listed_price
FROM products
ORDER BY price DESC, product_name ASC;

AS creates a readable column alias. ORDER BY sorts results: ASC is ascending and DESC is descending. If no direction is specified, ascending is commonly assumed.

4. Aggregate data with GROUP BY

SELECT country,
       COUNT(*) AS customer_count
FROM customers
GROUP BY country
ORDER BY customer_count DESC;

SELECT category,
       ROUND(AVG(price), 2) AS average_price,
       MIN(price) AS lowest_price,
       MAX(price) AS highest_price
FROM products
GROUP BY category;

-- Filter grouped results
SELECT country, COUNT(*) AS customer_count
FROM customers
GROUP BY country
HAVING COUNT(*) >= 5;
FunctionWhat it does
COUNT(*)Counts rows
SUM(column)Adds numeric values
AVG(column)Calculates an average
MIN(column)Finds the smallest value
MAX(column)Finds the largest value

Use WHERE to filter individual rows before grouping. Use HAVING to filter groups after aggregation.

5. JOIN tables together

-- Keep only matching customers and orders
SELECT c.customer_name, o.order_date, o.total_amount
FROM customers AS c
INNER JOIN orders AS o
  ON c.customer_id = o.customer_id;

-- Keep every customer, even without an order
SELECT c.customer_name, o.order_id
FROM customers AS c
LEFT JOIN orders AS o
  ON c.customer_id = o.customer_id;

INNER JOIN returns rows with matching keys in both tables. LEFT JOIN keeps every row from the left table and fills unmatched right-side columns with NULL. Check your join keys and row counts to avoid accidental duplicate totals.

6. Add logic with CASE

SELECT product_name, stock_quantity,
  CASE
    WHEN stock_quantity = 0 THEN 'Out of stock'
    WHEN stock_quantity < 10 THEN 'Reorder'
    ELSE 'In stock'
  END AS stock_status
FROM products;

CASE evaluates conditions in order and returns the first matching result. It is useful for labels, categories and simple business rules.

7. Insert, update and delete records

-- Add a row
INSERT INTO customers (customer_name, country)
VALUES ('Alex Morgan', 'Canada');

-- Update selected rows
UPDATE customers
SET country = 'United States'
WHERE customer_id = 42;

-- Delete selected rows
DELETE FROM customers
WHERE customer_id = 42;
Important safety rule

Never run UPDATE or DELETE without checking the WHERE condition. Without it, every row may be changed or deleted. Practise on a disposable copy and use transactions when supported.

8. Create a simple table

CREATE TABLE tasks (
  task_id INTEGER PRIMARY KEY,
  task_name VARCHAR(100) NOT NULL,
  is_complete BOOLEAN DEFAULT FALSE
);

CREATE TABLE defines a table. Common constraints include PRIMARY KEY, NOT NULL, UNIQUE and DEFAULT. Data types and auto-generated key syntax vary by database engine.

9. SQL query order: a quick memory aid

A typical query is written in this order:

SELECT column_name, COUNT(*)
FROM table_name
JOIN another_table ON ...
WHERE row_condition
GROUP BY column_name
HAVING COUNT(*) > 1
ORDER BY column_name DESC
LIMIT 10;

The database's logical processing order is broadly: FROM/JOIN, WHERE, GROUP BY, HAVING, SELECT, ORDER BY, then row limiting. This helps explain why a SELECT alias is not available in every earlier clause.

Common beginner questions

What are the most important SQL commands to learn first?

Start with SELECT, FROM, WHERE, ORDER BY and LIMIT. Then learn GROUP BY, aggregate functions and JOIN. Practise data changes only after you understand safe filtering.

Is SQL the same in every database?

No. Core ideas are shared, but date functions, data types, limiting rows, generated IDs and some advanced features differ. Check the documentation for the database you are using.
